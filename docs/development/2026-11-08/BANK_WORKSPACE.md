# Банк: каталог және кең есеп беті

Пайдаланушы мақұлдаған екі ұсыныс біріктірілді: тақырыптар каталогы мен ықшам тізім; есепті, редакторды және оқушы көрінісін толық енде ашу.

## Жұмыс ағындары

- Сол жақ каталог: барлық есептер, қолданылмайтын, тақырыпсыз, нақты тақырыптар мен есеп сандары, сақталған сүзгілер, оқушы жауаптары және себет. Тар экранда каталог жиналады.
- Тізім: серверлік іздеу (мәтін және `#ID`), күрделілік, сұрақ түрі, қолданылуы, тақырыптың болуы, бірнеше тақырыпты ANY/ALL сәйкестендіру, сұрыптау, 20/50/100 есептік беттеу.
- Есеп ашылғанда каталогтың орнына кең жұмыс беті келеді. «Есеп», «Өңдеу», «Оқушы көрінісі» режимдері ортақ пішін күйін пайдаланады. Сақталмаған өзгерісті алдын ала көру үшін сақтау қажет емес.
- Есепке сілтеме: `/admin/bank?task=125`, редактор: `?task=125&mode=edit`. Жаңа есеп: `?task=new&mode=edit`. Толық қайта жүктегенде есеп API-ден жаңадан оқылады.
- Сақтау есептің жаңа нұсқасын көрсетеді. Тізімге қайтқанда іздеу, сүзгілер, бет, scroll және PDF таңдауы сақталады. Сақталмаған пішіннен шығу, басқа сілтемеге өту немесе бетті жабу растауды сұрайды.
- Нұсқа қақтығысы сақтауды тоқтатып, жаңа нұсқаны жүктеуді ұсынады. Дубликат растауы, тарих, JSON өңдеу, rollback, қолданылу орындары және себет қолданыстағы механизмдерді пайдаланады.
- PDF таңдауы 100 есепке дейін, басқа беттер мен сүзгілерден жинауға болады. Экспорт алдында есептер бұрынғыдай API-ден қайта оқылады.
- JSON импорт/экспорт және рөлге сай сапа/журнал сілтемелері «Басқа әрекеттер» мәзірінде.

Тақырыптар каталогы қазіргі `bank_topics` тегтерінен алынады; жасанды иерархия немесе есептерді автоматты қайта жіктеу қосылмады. Жаңа schema migration қажет емес. Жоба/тексеруде/дайын статустары бөлек lifecycle өзгерісін талап етеді және бұл іске асыруда көрсетілмейді.

Сақталған сүзгілер аккаунтқа бөлінген browser localStorage ішінде, соңғы тізім күйі sessionStorage ішінде сақталады. Олар сервер арқылы басқа құрылғыларға синхрондалмайды. PDF таңдауы сол бет сессиясына тиесілі; аккаунт ауысқанда тазаланады.

## API

Жаңа `GET /api/admin/bank/catalog?q=...&limit=100` әкімші рөлін тексеріп, active/trash/unused/no-topics сандарын және есеп саны бар тақырыптарды қайтарады. Тақырып іздеуі серверде орындалады; тізімде ең көбі 100 тақырып көрсетіледі, қалғаны іздеумен табылады.

Бар және себет тізімдеріне қосылды:

- `question_type=input|tf|mcq|mcq6|select`
- `usage=all|used|unused`
- `has_topics=true|false`
- `topic_match=any|all`
- `sort=newest|oldest|updated`

Барлық сүзгілер pagination алдында SQL-де қолданылады. Тізім және жеке есеп GET-тері mutation-нан кейін ескі cache қолданбайды. Кеш келген іздеу/каталог/есеп жауаптары жаңа экран күйін алмастырмайды.

Сәйкестендіруден басқа сұрақ түріне ауысқанда `subquestions=[]` ескі өрістерді тазалайды. Empty array парсерде рұқсат етіледі, ал `select` үшін екі subquestion міндетті тексеруі сақталады.

## Тексеру

- TypeScript: `npm run typecheck`.
- Zero-warning ESLint: `npm run lint`.
- Next.js production build: `npm run build`.
- Python syntax және E9/F63/F7/F82 lint.
- `bot/tests/test_bank_catalog.py`: 10 000 есептік жеке SQLite базасында 6 тест. Pagination, ID/мәтін іздеуі, ANY/ALL, қолданылу, санақ, сұрыптау, auth, параметр валидациясы, type-change кезінде ескі options/subquestions тазалау тексерілді.
- Browser: негізгі 13 тексеру, телефонда 6 тексеру және себет/restore үшін 2 тексеру өтті. Нақты API-ге сақтау, тарих, іздеуді қалпына келтіру, сақталған сүзгі, екі беттен PDF таңдау және файл жүктеу, concurrent version conflict/reload, deep link reload, MathLive арқылы жаңа input есебін құру және көлденең overflow тексерілді.
- Desktop: 1440 px; mobile: 390 px. Есеп пен редакторда page-level көлденең overflow жоқ. Ұзын формулалар MathLive өрісінің ішінде жылжиды.

Browser тексеруінде OAuth сессиясы тек тест браузерінде mock етіледі. Backend сұраулары disposable `127.0.0.1:8100` fixture-ге жіберіледі. Production деректеріне жазылмайды. NextAuth/proxy authentication коды өзгертілмеді.

Қайта іске қосу:

1. `bot/` ішінде `venv/Scripts/python.exe scripts/preview_bank_workspace.py`.
2. `web/` ішінде `npm run build`, одан кейін `npm run start -- -p 3100`.
3. `web/` ішінде Playwright CLI сессиясын ашып, `run-code --filename tools/preview-bank-browser.js`, кейін `tools/check-bank-workspace.js` және `tools/check-bank-mobile.js` орындау.

Жергілікті QA файлдары `web/output/playwright/`: desktop/mobile PNG, `bank-workspace.pdf`. Олар Git-ке кірмейді. Бұл өзгеріс production-ға жарияланбады.
