# Сынақ тестіндегі көп деңгейлі папкалар

## Қолдану

Әкімші → Сынақ тесттері → **Папка қосу** арқылы негізгі немесе ішкі папка ашылады.
Мысалы: Қосымша тапсырма → Алгебра → Модуль теңдеулер → тесттер.
Тесттер тек ішкі папкасы жоқ папкаларға орналастырылады. Тесттері бар папкада
бірінші ішкі папка ашылғанда, диалог тест санын көрсетіп, олардың жаңа папкаға
түгел көшуін растауды сұрайды. Жасау мен көшіру бір транзакцияда орындалады.

Папка жолындағы **Өңдеу**, **Көшіру**, **Жою** әрекеттері атауды/ретті өзгертуге,
тармақты басқа жерге орналастыруға және бос папканы жоюға мүмкіндік береді.
Тесттің папкасы оның өңдеу терезесінде толық жолымен таңдалады. Өзін немесе
ұрпақтарын көшіру нысанасы ретінде таңдау мүмкін емес. Тесттері бар папкаға
басқа папка көшірілмейді; алдымен оның тесттерін ішкі папкаға жинау керек.
Ішкі папкасы немесе тесті бар папка жойылмайды.

Оқушыға тек тесті бар тармақтар көрінеді. Карточкадағы сан барлық ішкі
деңгейлердегі тесттерді қамтиды. Мазмұн жолы мен «Артқа» бір деңгей бойынша
жүреді; URL жаңартылғанда және браузердің back/forward әрекеттерінде сақталады.
Тесттің ID-і, нәтижелері, тапсырмалары және сақталған жауаптары өзгермейді.

## Деректер және үйлесімділік

- SQLite: Alembic `0014_trial_test_folders`; PostgreSQL: `0007_trial_test_folders`.
- `trial_test_folders`: тұрақты ID, parent ID, атау, рет. Бір деңгейдегі атаулар
  trim жасалғаннан кейін бірегей; атау ұзындығы 1–120 таңба. `/` атаудың бір бөлігі.
- `trial_tests.folder_id` папканы көрсетеді. Бастапқы категориялар негізгі
  папкаларға ауыстырылады. Миграция ескі бағандар мен тест ID-лерін сақтайды.
- `category` ескі клиенттер үшін негізгі папканың атауын сақтайды. Папканы
  көшіру/атауын өзгерту осы мәнді барлық ішкі тестте жаңартады. Ескі category
  сүзгісі негізгі тармақтың тесттерін қайтарады. `folder_id` сүзгісі нақты папканың
  тесттерін қайтарады; жазуда folder ID берілсе, сол ID қолданылады.
- Папка/тест орналастыру жазулары ортақ writer transaction қолданады:
  SQLite `BEGIN IMMEDIATE`, PostgreSQL transaction advisory lock. Тексеру мен
  жазудың арасындағы қатар сұраулар аралас папка не цикл жасай алмайды.
- Жаңа әкімші URL: `/admin/trial-tests/folder/{id}`; оқушы URL:
  `/trial-test?folderId={id}`. Бұрынғы атаулы URL-дер негізгі папканың ID-іне
  ауыстырылады, соның ішінде атаудағы `/`, `%` және literal `%2F` сақталады.

API:

| Әрекет | Бағыт |
| --- | --- |
| Тесті бар тармақтарды оқу | `GET /api/trial-tests/folders` |
| Барлық папканы оқу | `GET /api/admin/trial-tests/folders` |
| Папка ашу | `POST /api/admin/trial-tests/folders` |
| Атауын/ретін/ата-анасын өзгерту | `PATCH /api/admin/trial-tests/folders/{id}` |
| Бос папканы жою | `DELETE /api/admin/trial-tests/folders/{id}` |

Жазу әрекеттеріне қазіргі content-manage әкімші рұқсаты керек. Жаңа папка
payload-ы: `name`, `parent_id`, `sort_order`, `move_existing_tests`. PATCH ішінде
`parent_id: null` негізгі деңгейге көшіреді; өріс берілмесе ата-анасы сақталады.
Тест create/update FormData ішінде `folder_id` қабылдайды. Жоқ папкаға 404,
құрылым қайшылығына 409, қате атауға 400/422 қайтарылады.

  zero-warning ESLint өтті.
- Production build арқылы desktop/mobile Playwright: **24 passed**. Жаңа сценарий
  үш деңгей, тесттерді көшіру, draft, reload/back, бос тармақты жасыру,
  rename/reparent/delete және `/`/`%2F` атаулы ескі URL-ді тексереді.
- Production snapshot-тың 44 кестесі жеке, парольмен қорғалған жергілікті
  PostgreSQL-ға қалпына келтірілді. Миграциядан кейін бұрынғы 43 қолданба
  кестесінің барлық ескі бағандары бойынша мазмұн салыстырылды: өзгеріс жоқ,
  екі тесттің folder ID-лері анықталған, аралас папка жоқ. Көшірме/restore
  операциялары production-ға жазбаған.

## Жергілікті іске қосу және шығару

`python main.py` арқылы ашылған API код өзгергенде өзі қайта жүктелмейді.
Frontend жаңа папка API-ін сұрап, ескі backend `folders` сөзін `{test_id}` деп
қабылдаса, `path -> test_id: Input should be a valid integer` қатесі шығады.
Backend-ті қайта іске қосу қажет; Next dev server-ін жаңарту жеткіліксіз.
2026-11-04 жергілікті SQLite-тың жеке backup-ы алынып, API қайта іске қосылды:
папкалар 200 қайтарады, тест/нәтиже/draft сандары сақталды. Ашық Chrome
қойындысында нақты папка мен тесттің ашылғаны тексерілді.

Production реті: жеке backup → бөлек базаға restore және миграцияны тексеру →
CI → production schema migration → жаңа API deployment және health → API
promotion → web build және smoke → web promotion → folder ID/health/auth
тексерісі. PostgreSQL connection ашылған сәттегі кестелер тізімін сақтайды:
жаңа кестелер миграциясына дейін қыздырылған API процестерін қайта қолданбау
керек. Осы шығарылымда миграциядан кейін бөлек жаңа API deployment жасалды.
Hosted runtime-та
auto-migrate қосылмайды. Шығарылым дәлелі `evidence/trial-folders-release.json`
файлында сақталады.

Шығарылым **2026-11-05** күні аяқталды. API source: `1bea693`, әкімші:
`af70284`, web source: `0f47ad4`. [Толық CI](https://github.com/ernurreen-rgb/mathbott/actions/runs/41891814666)
алты job бойынша сәтті өтті. Production-дағы authenticated Chrome тексерісі
негізгі папкадағы екі тест пен сақталған жауаптардың «Жалғастыру» белгілерін
көрсетті. Production-да тесттік папка немесе тест жасалған жоқ.
[Docker шығарылымы](https://github.com/ernurreen-rgb/mathbott/actions/runs/41891814719)
да сәтті: екі image build, Trivy scan және Docker Hub push аяқталды.

Web rollback кезінде жаңа schema/API сақталсын: category үйлесімділігі ескі
интерфейске негізгі тармақтарды көрсетеді. Ішкі папкалар жасалғаннан кейін
ескі API-ге немесе schema downgrade-қа автоматты rollback жасамау керек;
ол жаңа folder байланысын жазбайды. Қалпына келтіру резервтік көшірмеге
арналған бөлек тексерілген процедурамен орындалады.
